Любое React-приложение имеет иерархическую структуру — дерево. На самой вершине всегда находится корневой компонент `App`. Он рендерит внутри себя крупные блоки (например, страницы или лейауты), которые, в свою очередь, состоят из более мелких компонентов. Данные в таком дереве по умолчанию текут строго сверху вниз: от родительских компонентов к дочерним.

Обычно внутри папки `src/` создается папка `components/`. Внутри неё для каждого компонента выделяется своя персональная папка. Например, для кнопки:

* `src/components/Button/Button.module.css` — изолированные стили.

Когда пользователь взаимодействует с элементами интерфейса (клики, ввод текста), React передает в функцию-обработчик специальный объект события. В React он называется `SyntheticEvent` — это кроссбраузерная обертка над нативным браузерным событием.

С его помощью мы можем получать введенные пользователем данные или отменять стандартное поведение браузера (например, перезагрузку страницы при отправке формы).



Каждый React-компонент проходит через три основные фазы жизненного цикла: 
  Mounting - Компонент впервые появляется на экране
  Updating - Компонент меняет свои пропсы или состояние. 
  Unmounting - Компонент удаляется со страницы
Для выполнения Side Effects - таких как запросы к серверу, настройка таймеров или подписка на глобальные события — на определенных этапах жизни компонента используется хук useEffect.
Он позволяет синхронизировать состояние компонента с внешними системами

Управлять кодом на разных этапах жизненного цикла компонента
useEffect(effect, dependencies)
effect - функция которую нужно выполнить
dependencies - необязательный массив, который контролирует когда функция выполняется


 Если компонент скрывается с экрана с помощью условного рендеринга (например, `{isVisible && <Component/>}`), происходит фаза размонтирования (**Unmount**)

 Если внутри вашего эффекта были настроены долгоживущие процессы (таймеры `setInterval` или слушатели событий на `window`), они продолжат работать в памяти браузера даже после исчезновения компонента, вызывая утечку памяти. Чтобы этого избежать, эффект должен возвращать функцию очистки (cleanup function).


 Массив зависимостей во втором аргументе `useEffect` указывает React, за какими именно переменными нужно следить.

  1) Массив отсутствует (`useEffect(() => {})`):** Эффект будет срабатывать **абсолютно при каждом рендере** компонента. Используется крайне редко.

  2) Массив пустой (`[]`):** Код выполнится один раз при старте (Mount).
  
  3) Массив с переменными (`[count, userId]`):** Эффект выполнится при монтировании, а затем будет перезапускаться **только тогда**, когда изменится хотя бы одна из указанных переменных.


Побочные эффекты часто создают асинхронные подписки или долгоживущие процессы в браузере. Если компонент исчезнет с экрана, эти процессы останутся в памяти, пытаясь обновить уже несуществующий компонент, что приведет к ошибкам и утечкам памяти.
Чтобы этого избежать, мы возвращаем из функции эффекта специальную **функцию очистки**:

useEffect(() => {
  // 1. Запускаем эффект
  return () => {
    // 2. Убираем за собой при размонтировании
  };
}, []);

Пример очистки таймеров и глобальных событий Типичный сценарий использования cleanup-функции — удаление слушателя событий с объекта `window` или сброс интервала: 

useEffect(() => { 
    const handleResize = () => console.log(window.innerWidth); window.addEventListener('resize', handleResize); 
    // Возвращаем функцию очистки 
    return () => { window.removeEventListener('resize', handleResize); }; 
  },[]);


  Утечка памяти (Memory Leak) 
  Утечка памяти в веб-приложении происходит тогда, когда удаленные из интерфейса элементы всё еще удерживаются в памяти браузера из-за забытых слушателей событий, интервалов или не отмененных сетевых запросов


  Чтобы отменять сетевые запросы `fetch`, если компонент успел размонтироваться до получения ответа, используется встроенный инструмент `AbortController`:

  useEffect(() => {
    const controller = new AbortController();
    
    fetch('/api/data', { signal: controller.signal })
      .then(res => res.json())
      .catch(err => {
        if (err.name === 'AbortError') console.log('Запрос отменен');
      });

    return () => controller.abort(); // Отменяем запрос при уходе
}, []);


При работе с реальной сетью данные приходят не мгновенно. Чтобы интерфейс не выглядел сломанным, пока сервер обрабатывает запрос, обязательно внедряется состояние загрузки (например, `const [isLoading, setIsLoading] = useState(true)`). 

Перед вызовом `fetch` мы ставим этот флаг в `true`, а в блоках `.then()` или `.finally()` сбрасываем в `false`. Это позволяет показывать пользователю аккуратный спиннер или надпись «Загрузка...» во время ожидания.


Два незыблемых правила работы с хуками (Rules of Hooks):
1. Хуки можно вызывать **только на самом верхнем уровне** функциональных компонентов. Нельзя оборачивать их в условия `if`, циклы `for` или вложенные функции.
2. Хуки можно вызывать **только внутри компонентов React** или внутри кастомных хуков. В обычных JS-функциях они работать не будут.

Пагинация - разделение данных на страницы
Логика пагинации строится на хранении в состоянии текущего номера страницы например, const [currentPage, setCurrentPage] = useState(1)
и количества элементов на одну страницу itemsPerPage. 
На основе этих данных мы вычисляем индексы для обрезки массива данных перед рендерингом.

Для выделения элементов текущей страницы из общего массива используется метод `.slice()`:
const indexOfLastItem = currentPage * itemsPerPage;
const indexOfFirstItem = indexOfLastItem - itemsPerPage;
const currentItems = allItems.slice(indexOfFirstItem, indexOfLastItem);
